# Research Daily Report

一个用于生成**科研 / 工程日报**的技能包（skill）。

它根据当天的对话记录、实验过程、终端命令与日志、代码改动和调试过程，
重建「你当天到底在研究什么、怎么想、试了什么、得到什么结论」，
而不是输出一份 Git changelog。

面向场景：机器人、强化学习、仿真、算法开发、实验与调试、论文复现。

## 核心原则

不能用「改了哪些文件」来代替「解决了什么问题」。

报告的主线是问题求解过程：

```
目标 → 观察 → 假设/推断 → 尝试 → 结果 → 解释 → 解决 → 遗留问题 → 下一步
```

并非每个任务都需要走完全部阶段，但必须让用户在几周之后仍能看懂：

1. 当时在排查什么？
2. 为什么要排查它？
3. 观察到了什么现象？
4. 怀疑的原因是什么？
5. 实际尝试了哪些方法？
6. 每次尝试之后发生了什么？
7. 哪些假设被支持、哪些被排除？
8. 真正解决了什么？是怎么解决的？
9. 还有什么没解决？
10. 下一步应该查什么？

## 关键约束

技能内置了若干「真实性规则」，用于防止把过程写成结论：

| 不允许的等价替换 | 说明 |
| --- | --- |
| 助手建议 → 已执行 | 建议了但没做，只能说「考虑过」 |
| 用户假设 → 已确认原因 | 假设在获得证据前始终是假设 |
| 已尝试 → 已解决 | 做了改动不等于问题解决 |
| 代码已改 → 已验证 | 改代码本身不是验证 |
| 计划做 → 已完成 | 明确的区分 |

如果代码改了但结果没测，应写「已完成修改，效果尚待验证」，
而不是「问题已解决」。失败的尝试如果排除了某些可能性，也要保留。

## 目录结构

```
.
├── SKILL.md                        # 技能定义与完整写作规范
├── README.md                       # 本文件
├── CHANGELOG.md                    # 变更历史
└── references/
    ├── report-guidelines.md        # 补充写作指南（假设演化、证据分级、措辞校准）
    └── example-report.md           # 示例日报，展示期望的推理还原程度
```

- `SKILL.md` 是入口，包含证据来源优先级、证据分类、任务归并、写作风格、
  报告结构和最终一致性自检清单。
- `references/` 下的文件按需读取：写报告时用于参考，不参与主流程。

## 使用方式

将本目录作为技能安装到你的 agent 技能目录中，使其可由
「写日报 / 研究日志 / experiment log / debugging summary」等请求触发。

触发后 agent 会：

1. 收集当天的对话、实验、日志与代码改动作为证据；
2. 按「问题求解线程」而不是时间顺序或文件顺序归并任务；
3. 区分观察、假设、尝试、结果与结论，保留不确定性；
4. 输出含「今日结论」和「未解决问题与下一步」的中文报告。

## 设计取向

- **对话优先于 diff**：实验动机、被排除的解释、取舍理由通常只存在于对话里。
- **保留负结果**：排除某个方向本身就是进展。
- **不做过度宣称**：措辞随证据强度分级（验证表明 / 结果支持 / 目前更倾向于 / 推测）。
- **不做模板填空**：按当天实际工作选择章节，只有一件事就只写一节。
