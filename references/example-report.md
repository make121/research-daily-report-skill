# 日报

## 1. 三任务切换教师策略测试

更换技能数据集后重新训练三任务切换教师策略，并重点检查不同技能之间的
切换表现。

从测试结果来看，当当前机器人状态与目标技能所需状态比较接近时，策略能够
完成较自然的切换；但在部分不稳定状态下，切换后仍可能出现较大的跟踪误差，
最终触发环境 reset。

当前三技能之间的切换覆盖率仍然偏低。直接提高覆盖率会明显增加训练压力，
因此现阶段暂未通过大幅扩展切换组合来解决这一问题。

另外，当前使用的技能在运动形式上相对接近，且高动态动作较少，这可能也是
教师策略和后续学生策略较容易学习这些技能的原因。因此，目前的测试结果还
不足以说明策略在差异较大的高动态技能之间也具有同样的切换能力。

## 2. 学生策略学习能力验证

为了进一步判断问题主要来自“多技能本身难以学习”，还是来自技能之间的
切换状态覆盖，先单独训练了一个学生策略进行测试。

测试中学生策略的整体表现与教师策略较为接近，说明当前技能集合本身可以被
学生策略学习。

结合教师和学生策略的表现，目前更倾向于认为主要问题集中在不同技能之间的
状态覆盖和切换稳定性，而不是单纯的学生策略容量或多技能学习失败。

不过，由于当前技能之间相似程度较高，这一判断仍需要在差异更大的动作组合
上进一步验证。

## 3. 恢复技能缺失问题

当前策略在技能切换产生较大误差或机器人进入明显不稳定状态后，环境会直接
reset，尚未包含 fall-down / get-up 类型的恢复技能。

这意味着当前系统只能测试正常状态附近的技能切换，而难以验证策略能否从
较大姿态偏差甚至倒地状态恢复后继续执行其他技能。

因此计划将 get-up 作为恢复技能加入当前技能集合，使异常状态能够通过策略
自身恢复，而不是直接依赖环境 reset。

## 4. Get-up 数据重定向检查

首先对 get-up 数据重新进行 retarget。

回放部分重定向后的数据时发现明显异常：左腿在起身过程中持续发生内旋，
最终站立后脚尖朝向与 base 朝向相反。

进一步观察后发现，该问题并不是突然发生的姿态跳变，而是在动作过程中持续
累积的旋转。因此问题不像是某个单独帧的数据异常，更可能与关节旋转方向、
坐标系定义或 retarget 中的旋转映射有关。

针对这一判断，开始调整重定向流程，并对相关关节的三个旋转方向进行取反
测试，以检查是否能够修正最终的腿部朝向。

目前该修改仍需要通过重新生成并回放 get-up 动作进一步验证，因此暂不能
认为该问题已经完全解决。

## 今日结论

今天主要完成了三任务切换策略和学生策略的初步验证，并进一步缩小了当前
问题范围。

现有结果表明，当前技能集合本身可以被学生策略学习；相比单纯的多技能学习
能力，跨技能状态覆盖不足和异常状态恢复能力缺失可能是后续更需要关注的
问题。

同时，在准备加入 get-up 恢复技能时发现 retarget 后左腿持续内旋的问题。
通过动作回放初步排除了单帧跳变，目前正在重点检查关节旋转方向和坐标系
映射。

## 未解决问题与下一步

1. 完成 get-up retarget 修正后的动作回放，验证左腿方向异常是否消失。
2. 检查旋转方向修改是否会影响其他 get-up 动作。
3. 将验证后的 get-up 动作加入恢复技能。
4. 重新测试包含恢复技能后的三任务切换策略。
5. 后续考虑加入与当前技能差异更大的高动态动作，进一步验证技能切换能力。
